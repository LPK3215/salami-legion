# 跨端操作与布局方案

> 本文说明网页版《蚕食军团》在**电脑端**与**移动端**上的完整交互设计：
> 操作方式、输入优先级、屏幕布局、断点适配、异常场景处理，以及背后的参数取值。
> 对应代码：`js/engine.js`（输入与渲染）、`css/style.css`（布局）、`js/ui.js`（设置与提示）。

---

## 1. 设计目标

| 目标 | 具体做法 |
|---|---|
| 两端都不需要教程就能上手 | 鼠标跟随 + 虚拟摇杆，都是最符合直觉的交互范式；首次进入有设备相关的引导浮层 |
| 操作精确、有反馈 | 摇杆有可见基座/手柄且**中心锁定**、鼠标有十字准星；松手后的行为由「惯性」开关明码标价 |
| 双端不会互相干扰 | 输入按「最后使用的设备」互斥，换设备自动清掉上一设备的状态 |
| 多指同时操作不冲突 | 摇杆独占第一根手指，技能按钮独立响应第二根手指 |
| 不给玩家制造意外 | 禁掉下拉刷新、双指缩放、长按菜单；切后台自动暂停 |
| 各种屏幕都好看 | 刘海安全区、横竖屏、窄屏、超宽屏分别适配 |

---

## 2. 设备识别与操作方式

游戏提供三种操作方式，可在**主菜单 → 操作**按钮循环切换（自动 → 摇杆 → 跟随），设置保存在存档里。

| 模式 | 触屏行为 | 鼠标行为 |
|---|---|---|
| **自动**（默认） | 虚拟摇杆 | 指针跟随 |
| **摇杆** | 虚拟摇杆 | 指针跟随（鼠标不适合摇杆） |
| **跟随** | 手指跟随（点哪走哪） | 指针跟随 |

判定逻辑（`engine.js`）：

```js
const useStick = (t) => t !== 'mouse' && this.controlMode !== 'follow';
```

> 鼠标永远不会走摇杆逻辑——鼠标有持久光标，摇杆对它是负优化。

## 3. 电脑端方案

### 3.1 鼠标直接控制方向

- **移动鼠标即可移动军团**：指针所在位置会被换算成世界坐标，军团持续朝该点移动。
- 在目标点绘制**脉冲十字准星**（`drawTargetMarker`），让「指哪打哪」一目了然；
  目标点距离军团小于 46px 时不绘制，避免准星压在军团身上。
- 指针跟随不要求按住鼠标——这是 IO 类游戏的通用直觉。

### 3.2 键盘操作

| 按键 | 作用 |
|---|---|
| `W` `A` `S` `D` | 上 / 左 / 下 / 右移动 |
| `↑` `←` `↓` `→` | 同上，与 WASD 完全等价 |
| `空格` / `E` / `K` | 释放技能 |
| `Esc` / `P` | 暂停 / 继续 |
| 同时按两个方向 | **斜向移动**（方向向量自动归一化，不会斜着变快） |

关键实现：用**「按住集合」**推导方向，而不是每次按键直接覆盖：

```js
this._held = new Set();          // 记录当前按住的方向
this._syncKeys = () => {         // 由集合推导出 x / y
  let x = 0, y = 0;
  if (this._held.has('left'))  x -= 1;
  if (this._held.has('right')) x += 1;
  if (this._held.has('up'))    y -= 1;
  if (this._held.has('down'))  y += 1;
  this.keys.x = x; this.keys.y = y;
};
```

> 如果改成「每次 keydown 直接赋值」，同时按 `W` + `D` 会丢掉前一个方向，斜向移动就失效了。

**惯性而行与键盘**：键盘是「按住转向」模型 —— 按着时实时跟随方向；松开全部方向键后默认
**沿最后方向继续走**（`settings.glide`，主菜单「惯性」可关），同时按住两个相反方向（`A+D` / `W+S`）算作**主动刹车**。

### 3.3 鼠标与键盘混用

- 两者可以随时切换，**谁最后操作就听谁的**。
- 键盘按下期间优先响应键盘；松开后若鼠标仍处于有效位置，鼠标一动就交还给鼠标跟随。
- 键盘操作不会把鼠标状态清空，所以「键盘绕后 → 松手（惯性滑行）→ 鼠标一动接管」非常顺滑。

## 4. 移动端方案

### 4.1 虚拟摇杆（默认）

- **按住屏幕任意位置**即生成摇杆基座，**拖动方向 = 移动方向，拖动距离 = 移动速度**。
- 摇杆基座出现在手指按下的地方（靠近边缘时会往里收），所以左手/右手、横屏/竖屏都顺手，不需要去够固定按钮。
- 视觉反馈由引擎实时绘制：半透明基座圆 + 死区圆 + 方向连线 + 彩色手柄（取当前皮肤颜色）。

参数与手感（`engine.js`）：

| 参数 | 取值 | 说明 |
|---|---|---|
| 摇杆半径 `maxR` | `clamp(min(屏宽,屏高) × 0.17, 46, 96)` px | 随屏幕自适应 |
| 死区 `DEAD` | 14% | 手指轻微抖动不产生移动，避免「站着乱走」 |
| 满速点 `FULL` | 72% | 拉到 72% 半径即满速，手感更跟手 |
| 力度曲线 | `(raw - 0.14) / (0.72 - 0.14)` | 线性映射，0～1 |
| 目标距离 | `430px × 力度` | 力度小则目标点近，军团走得慢 |
| **中心锚定**（`anchorStick`，默认开） | 按下瞬间把原点收进「距四边 ≥ maxR」的安全区，**之后不再移动** | 360° 都有完整行程；手指拖出半径只把向量收在圆周上，方向与满力度保留 |

> **为什么要锁住中心（旧版是一个真 bug）**：旧实现是「橡皮筋」——手指超出半径时把**基座整体往手指方向平移**。
> 于是手游玩家习惯在下半屏操作，手指一路往下拖，基座就一路跟着爬，到屏幕物理边缘后**再也没行程**，
> 表现为「拖着拖着就拖出屏幕了、只能取消掉重新按」。锁定中心 + 向量钳制后，行程恒定，不再越用越短。
> 代价：在贴边位置按下时，基座会比你手指略高/略偏一个 `maxR`（为的是把那个方向的行程留出来）。

### 4.2 多指安全（重点）

手机玩家几乎一定会「一根手指控制方向，另一根手指点技能」，因此：

1. **摇杆独占第一根按在画布上的手指**（记录 `pointerId`），其他手指的按下/移动一律忽略；
2. 技能按钮是**独立的 DOM 元素**，位于 HUD 层（`pointer-events:auto`），
   点它不会传给画布，所以不会打断摇杆；
3. 通过 `setPointerCapture` 把摇杆手指「锁」在画布上，手指滑出画布也不会丢事件。

实测验证（`npm test`）：

```
✓ 多指互不干扰：第二根手指无法抢走摇杆
✓ 多指同时操作：摇杆 + 技能按钮可同时使用
```

### 4.3 惯性而行（默认开）与主动刹车

军团的目标点由「方向 + 力度」决定，而不是由「按没按着」决定：

- **手指/按键还按着**：实时控制，拉多少算多少；
- **全部抬起 / 松开**：进入 **巡航（`cruise`）** —— 锁定最后一次有效方向与力度，军团**继续往前走**；
- **主动刹车**（两种方式）：把摇杆**拉回中心死区**，或同时按住两个相反方向键（`A+D` / `W+S`）。

开关在**主菜单 → 惯性**（存档字段 `settings.glide`，默认 `true`），切换会**实时同步到当前对局**；
关掉后就是旧行为「松手即停」（引擎使用平滑加速度，仍有 ≈10px 的惯性收尾，占比 <25%）。

> 设计取舍：本作是「一个都不停」的吞噬游戏，抬手就停会让触屏玩家的手指疲劳且无法做弧形走位；
> 但「保持行进」确实会改变新手的心理模型，所以它**必须是显式开关 + 可刹车**，而不是隐式行为。
> 换操控设备时巡航一律作废：触屏按下、鼠标一动、切后台都会 `cruise.strength = 0`。

### 4.4 跟随手指模式

如果习惯《拥挤城市》那类「点哪走哪」，可在主菜单把操作切成**跟随**：
触点位置直接换算成世界坐标作为军团目标，抬手即停。适合大屏平板单手操作。

## 5. 输入优先级与状态机

每帧 `updateControl()` 按固定优先级决定军团目标点：

```
① 虚拟摇杆（手指按着）            → 有方向：目标 = 中心 + 方向 × 430 × 力度（并写入巡航）
                                   → 回到死区：目标 = 中心（主动刹车，清空巡航）
② 键盘（有方向键按住）            → 目标 = 中心 + 方向 × 430（斜向已归一化，并写入巡航）
③ 相反方向键互抵（A+D / W+S）      → 目标 = 中心（主动刹车，清空巡航）
④ 全部松开 + 惯性开启            → 目标 = 中心 + 巡航方向 × 430 × 巡航力度
⑤ 全部松开 + 惯性关闭            → 目标 = 中心（立刻停下）
⑥ 指针跟随（鼠标 / 跟随手指模式）  → 目标 = 指针所在世界坐标（同时作废巡航）
```

状态标记 `lastInput`（`idle | stick | keys | cruise | pointer`）用于区分上面几步；
巡航状态本体是 `cruise = { x, y, strength }`（方向 + 力度，`strength=0` 即没在巡航）。

**换设备时的状态清理**：触屏按下时会主动清空鼠标跟随状态（`pointer.active = false`），
否则会出现「触屏松手后，军团又被残留的鼠标位置拖走」的诡异行为（这个 bug 就是被自动化测试抓出来的）。

**异常场景**：

| 场景 | 处理 |
|---|---|
| 切到后台 / 屏幕锁定 | `visibilitychange` → 松开所有输入 + 自动暂停，回到前台点「继续」 |
| 窗口失焦 | `blur` → 松开所有输入，避免「卡住一直走」 |
| 右键 | 画布上阻止 `contextmenu`，游戏中不会弹菜单 |
| 双击 / 双指缩放 | 阻止 `gesturestart/gesturechange/dblclick`，配合 `touch-action:none` |
| 下拉刷新、橡皮筋滚动 | `html/body { overscroll-behavior: none }` |
| 长按选中文字 | `user-select:none` + `-webkit-tap-highlight-color:transparent` |

## 6. 布局方案

### 6.1 对局屏幕分区

```
┌──────────────────────────────────────────────────────────┐
│ [安全区]                                                  │
│  第 N 关  目标：达到 XX 人        00:12         [❚❚]      │  ← 顶部 HUD
│  ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░                              │     关卡/目标/进度条 · 计时 · 暂停
│                                                          │
│                                                          │
│                    ◜◝   ← 战场（Canvas 全屏）             │
│                   (军团)                                  │
│                                                          │
│                                                          │
│  ┌────────┐                       我方军团         ╭──╮   │
│  │ 小地图 │                        128            │速│   │  ← 底部 HUD
│  └────────┘                     [增益标签]         ╰──╯   │     小地图+敌军列表 · 人数 · 技能按钮
│  ●红队 42  ●紫队 18                            急速集结   │
│ [安全区]                                                  │
└──────────────────────────────────────────────────────────┘
```

- **HUD 整层 `pointer-events:none`**，只有按钮 `pointer-events:auto` → 除了按钮，屏幕任何地方都能起摇杆。
- 顶部/底部 HUD 都加了 `env(safe-area-inset-*)`，刘海屏、挖孔屏、横屏手势条都不会遮挡内容。
- 超宽屏（≥1400px）时 HUD 内容限制在 1500px 内并居中，避免小地图和技能按钮被甩到屏幕两个角。
- 顶部左上角的关卡标题在**无尽模式**下会变成「无尽模式 · 战场半径 N」，
  把动态战场随人数长大的过程直接显示出来（主线仍显示「第 N 关 · 关卡名」）。
- **小地图在无尽模式下显示的是「当前战场框」**（以玩家为中心的那块动态地图），
  所以你永远在小地图正中间，周围的内容随你移动换位置。

### 6.2 断点与设备适配

| 条件 | 适配内容 |
|---|---|
| `max-width: 520px`（窄屏手机） | 标题缩小、关卡格子 2 列、小地图 104×78、奖励卡改为横向卡片 |
| `max-height: 520px`（横屏手机） | **隐藏小地图和增益标签**、人数数字缩小、优先保证战场可视面积 |
| `pointer: coarse`（触屏） | **技能按钮 74→88px**、徽章 54px、暂停按钮 44→48px、底部整体抬高 20px、去除 hover 位移效果 |
| `pointer: coarse` + 窄屏 | 技能按钮折中 78px，避免占掉太多横向空间 |
| `hover: hover`（有鼠标） | 按钮亮度提升、卡片上浮、边框高亮等 hover 反馈 |
| `min-width: 1400px`（大屏） | HUD 居中限宽、内容页最大 820px |

### 6.3 触控目标尺寸

遵循移动端最小点击目标规范（≥44px，推荐 48px）：

| 元素 | 桌面 | 触屏 | 说明 |
|---|---|---|---|
| 技能按钮 | 74px | 88px（窄屏 78px） | 拇指高频操作，必须够大 |
| 暂停按钮 | 44px | 48px | |
| 普通按钮 `.btn` | 48px 高 | 48px 高 + 更大字号 | 触发区域 ≥ 48px |
| 小按钮 `.btn-tiny` | 40px 高 | 40px 高 | 设置类，非高频 |

所有可点元素统一加 `touch-action: manipulation`，消除移动端 300ms 点击延迟与双击缩放误判。

## 7. 引导与提示

- 进入第 1 关 / 开始一轮无尽挑战时显示引导浮层，**文案随设备与操作方式自动变化**：
  - 触屏 + 摇杆：`按住屏幕拖动，虚拟摇杆控制方向 / 拖得越远走得越快，松手后保持方向继续走`（关掉惯性时末句变为「松手即停」）
  - 触屏 + 跟随：`按住屏幕，军团朝手指位置移动`
  - 桌面：`移动鼠标控制方向 / WASD 方向键同样可用 · 空格放技能`
- 玩家第一次触摸/点击屏幕时浮层立即消失（不挡操作）。
- 主菜单「操作」按钮切换时会弹 toast 说明当前模式的含义。
- 「玩法说明」页分别列出**电脑端**与**移动端**的完整操作表。

改完输入或布局相关代码后，按这张表过一遍：

**电脑端**
- [ ] 移动鼠标，军团跟随，目标点出现十字准星
- [ ] `W A S D` 四个方向都能走；`W`+`D` 能斜向走
- [ ] 方向键与 WASD 行为一致
- [ ] 松开方向键后沿原方向继续走（惯性开启时）；`A+D` 同时按住能真的停下
- [ ] 主菜单把「惯性」切到「松手即停」后，松开方向键立即停下（≈10px 收尾）
- [ ] `空格` / `E` 放技能，`Esc` 暂停并显示遮罩，再按继续
- [ ] 鼠标和键盘交替使用不会「打架」（鼠标一动就能接管巡航）
- [ ] 画布上点右键不弹菜单

**移动端**
- [ ] 按住屏幕出现摇杆，拖动方向正确，拖得越远走得越快
- [ ] 轻微抖动不移动（死区），拖出死区立刻响应
- [ ] **在下半屏一直往一个方向拖，基座不会跟着手指跑出去**，360° 都能拉满

- [ ] 松手后保持方向；把摇杆拉回中心再松手能停下

**布局**
- [ ] 竖屏 / 横屏都完整可用，关键 HUD 不被刘海或手势条遮挡
